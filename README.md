# CS:ZONE — сайт компьютерного клуба

Статический сайт. Никакой сборки и зависимостей: залил папку на хостинг — работает.

## Что внутри

```
index.html        Главная: герой с логотипом, зоны, карта зала, цены, галерея, правила
prices.html       Цены: заставка, тарифы по зонам, переключатель будни/выходные, ночь, марафон
hardware.html     Железо: сравнение STANDART и BOOTCAMP
promos.html       Акции
contacts.html     Контакты + витрина Яндекс.Карт
booking.html      Забронировать: выбор места на карте зала + заявка
rules.html        Правила клуба (перенесены с картинки в текст)
robots.txt, sitemap.xml
status.example.json  Запасной файл занятости мест (см. раздел ниже)
build.py          Генератор страниц (шапка/подвал в одном месте)
assets/css/main.css
assets/js/main.js
assets/img/       Логотип, фон-небо, фото зала, favicon, OG-обложка
assets/video/     intro.mp4 — старая заставка, стоит на странице «Цены»
```

## Публикация

Загрузить всё содержимое папки в корень хостинга. `index.html` — главная.

Единственная внешняя зависимость — шрифты Google Fonts (Tektur, Manrope,
JetBrains Mono) и виджет Яндекс.Карт. Если хостинг в стране, где Google Fonts
блокируются, шрифты стоит положить локально: скачать с fonts.google.com,
положить в `assets/fonts/` и заменить `<link>` в шапке на `@font-face`.

## Железо

`assets/js/main.js`, объект `SPECS` в самом верху — единственный источник правды.
Из него берут данные сразу три места: страница «Железо», подсказка при наведении
на место в карте зала и панель выбранного места на странице брони. Поменяли
видеокарту в одном месте — обновилось всюду.

```js
var SPECS = {
  standart: { label:'STANDART',
    core:[['Процессор','Intel Core i5-10400F'], ['Видеокарта','RTX 2060 SUPER 8 ГБ'], …],
    gear:[['Монитор','ASUS, 165 Гц, 25/27″'], ['Клавиатура','ASUS TUF Gaming K3'], …] },
  bootcamp: { … },
  tv: { core:[['Экран','Телевизор 65″']], gear:[] }
};
```

`core` — системный блок, `gear` — периферия; между ними в таблице рисуется
разделитель, как на фирменной картинке клуба.

## Прайс

`assets/js/main.js`, объект `PRICES`. Заполнен по фирменному прайсу клуба.
Из него собираются страница «Цены» и блок «От 120 ₽ за час» на главной —
цифры в двух местах не разойдутся.

```js
zones: [
  { name:'Зал STANDART', sub:'RTX 2060 SUPER · 165 Гц · №06–30',
    weekday:{ day:[120,320,470], eve:[130,340,510] },
    weekend:{ day:[130,340,510], eve:[150,400,590] } },
  …
]
```

Внутри `day`/`eve` три числа — это 1 час, 3 часа, 5 часов, в том же порядке,
что в `packs`. Отдельно лежат `night` (21:00–08:00) и `marathon` (24 часа).

Цена за час («≈ 94 ₽/час») не хранится, а считается делением: стоимость пакета
на его длительность. Меняете цену — пересчитается сама.

Два временных окна: `day` — 08:00–17:00, `eve` — 17:00–08:00 (подтверждено клубом).

## Акции

Тот же файл, массив `PROMOS`: `mark` (крупная надпись-выноска), `title`,
`text`, `cond` (условия). Новая акция — новый объект в массиве.

Марафон 24 часа на фирменном прайсе стоял под шапкой «Акции», но по смыслу это
тариф, поэтому он живёт на странице «Цены». Если нужно продвигать его как акцию —
добавьте в `PROMOS`.

```js
var PRICES = [
  { zone: 'Зал STANDART', rows: [
      ['1 час',              '150 ₽'],
      ['Ночь 22:00–08:00',   '700 ₽'] ] },
  { zone: 'Буткемп', rows: [ ['1 час', '200 ₽'] ] }
];

var PROMOS = [
  { title: 'Счастливые часы', when: 'Будни до 16:00', text: 'Условия акции.' }
];

```

## Как правится структура зала

В том же `main.js`, сверху:

```js
var HALL = [
  { key:'bootcamp1', title:'Буткемп I',    meta:'5 мест · №01–05',  from:1,  to:5  },
  { key:'standart',  title:'Зал STANDART', meta:'25 мест · №06–30', from:6,  to:30 },
  { key:'bootcamp2', title:'Буткемп II',   meta:'6 мест · №31–36',  from:31, to:36 }
];
```

Нумерация подтверждена заказчиком: 5 + 25 + 6 = 36. Зона автоматически знает,
какая конфигурация в ней стоит, — через `ZONE_SPEC`.

## Правки текста в шапке и подвале

Шапка и подвал у всех страниц общие и лежат в `build.py`. Поменяли — запустили
`python3 build.py`, все семь страниц перегенерировались. Можно и руками по

## Занятость мест (данные из Gizmo)

Карта зала умеет показывать занятость: свободно — зелёная точка, занято —
тёмная плитка без точки, выключен — приглушённая. Занятое место нельзя выбрать
в брони, но железо по наведению показывается всё равно.

Данные берутся из **API клуба** — Cloudflare Worker поверх Gizmo:

```
https://cszone-status-api.sburchinskij1.workers.dev/api/pcs
```

Ответ:

```json
{ "updatedAt": "2026-08-04T15:45:48.099Z",
  "totals": { "all": 31, "free": 19, "occupied": 9,
              "reserved": 0, "unavailable": 3 },
  "computers": [
    { "number": 1, "name": "PC-001", "status": "occupied",
      "isOutOfOrder": false, "isLocked": false }
  ] }
```

Статусы раскладываются на карте так: `free` — свободно (зелёная точка),
`occupied` — занято, `reserved` — бронь (холодная синяя плитка),
`unavailable` — недоступно. Машины с `isOutOfOrder` или `isLocked`
считаются недоступными независимо от статуса.

**API знает не про все 36 мест.** Сейчас он отдаёт 31 машину — номеров 15–19
в выдаче нет, эти машины сняты с линии. Они помечены вручную: подпись
«Не работает», плитка приглушена, выбрать нельзя. Список — константа
`OUT_OF_SERVICE` в начале `assets/js/main.js`:

```js
var OUT_OF_SERVICE = [15, 16, 17, 18, 19];
```

Машина вернулась в строй — убрать номер отсюда, больше нигде править
не нужно. Живые статусы такие места не трогают: даже если API вдруг
начнёт их отдавать, пометка «не работает» останется, пока номер в списке.

Если в ответе не окажется какого-то другого номера, он просто останется
без статуса — кликабельным, как раньше, а занятость по нему подтвердит
администратор.

Настройки — в начале блока «ЗАНЯТОСТЬ МЕСТ» в `assets/js/main.js`:
`url` (адрес API), `fallback` (запасной локальный `status.json` старого
формата), `pollMs` (как часто опрашивать, по умолчанию 30 секунд) и
`maxAgeSec` (600 секунд — старше считается неактуальным).

### CORS

Запрос идёт из браузера гостя, поэтому воркер обязан отдавать заголовок

```
Access-Control-Allow-Origin: https://ваш-домен
```

(или `*`). Без него браузер заблокирует ответ, и карта просто останется
без статусов — сайт при этом не сломается. Если после публикации плашка
«Данные из клуба» не появляется, начинать проверку нужно с этого заголовка:
консоль браузера напишет про CORS прямым текстом.

### Что делает агент на стороне клуба

Занятость собирает воркер, который опрашивает Gizmo. Логика та же, что
описана ниже для агента — на сайт попадает только «номер → статус»:

1. дёргает локальный Web API Gizmo (`http://localhost:{порт}`, HTTP Basic,
   учётные данные оператора) и берёт список хостов с их состоянием;
2. отбрасывает всё лишнее — имена пользователей, баланс, длительность сессии
   на сайт не попадают, только «номер → free/busy/off»;
3. отправляет результат POST-запросом на хостинг, где маленький скрипт
   с общим секретом перезаписывает `status.json`.

Опрос идёт изнутри наружу. Никакие порты на компьютере администратора
открывать не надо, статический IP не нужен, доступ к базе Gizmo из интернета
не появляется. Учётные данные Gizmo остаются на машине клуба.

### Что делает сайт, если данных нет

API не ответил, отдал битый JSON, данные старше `maxAgeSec`, заблокирован
CORS — сайт пробует запасной `status.json` рядом с `index.html`, а если нет
и его, карта тихо возвращается к обычному виду: все места без статусов
и доступны к брони. Ошибка на стороне клуба сайт не ломает. Плашка «Данные
из клуба» показывается только когда данные свежие.

### Что нужно, чтобы дописать агента

- Web API включён в настройках сервера Gizmo (общие настройки, порт по
  умолчанию 8080).
- Список команд Gizmo отдаёт сам: открыть в браузере на компьютере
  администратора `http://localhost:8080` — это и есть документация конкретной
  версии. Нужен ответ метода со списком хостов.
- Хостинг, который умеет принимать POST (PHP-файл или serverless-функция).
  Тот же скрипт заодно отправляет заявки на бронь в Telegram.

## Бронь: как это работает сейчас

Бэкенда нет, поэтому заявка не «улетает на сервер». Форма собирает текст заявки,
кладёт его в буфер обмена и открывает чат **администратора** `@cszone_admin`
в Telegram — гостю остаётся вставить и отправить. Плюс кнопка звонка.

Канал клуба `@cszoneclub` и администратор `@cszone_admin` разведены намеренно:
бронь идёт человеку, анонсы и акции ведут в канал. Обе ссылки заданы
константами `TG` и `TG_ADMIN` в `build.py` и объектом `CLUB` в `main.js`.

Работает без хостинга с PHP и без базы. Если нужно, чтобы заявки приходили
сами — делается Telegram-бот: 20 строк на стороне сайта, заявка падает
в чат администратора мгновенно. Это следующий шаг, если заказчик захочет.

## Чего не хватает от заказчика

1. **Домен** — подставить в `robots.txt` и `sitemap.xml` вместо `example.com`.
2. Соцсети кроме Telegram, если есть.
3. Модель телевизоров в ТВ-зонах — пока указано только «65″».
4. **Проверить CORS на воркере** — см. раздел «Занятость мест».

## Отзывы

Блок отзывов стоит на главной (компактный) и на «Контактах» (полный).
Заголовок — «Наша оценка всегда 5», под ним две карточки оценок: Яндекс.Карты
и 2ГИС, каждая ведёт в карточку клуба. Кнопки рядом — «Отзывы на Яндексе»
и «Отзывы в 2ГИС».

Раньше здесь стоял iframe-бейдж Яндекса. Убран: чужой виджет тянет сторонний
скрипт, живёт в своей теме и не отрисовывается, если карточка в Яндекс Бизнесе
не подтверждена. Свои карточки грузятся мгновенно и не зависят ни от чего.
Оценки в них проставлены вручную — если рейтинг где-то просядет, цифру нужно
поправить в `reviews()` в `build.py`.

Текст отзывов на сайте не дублируется намеренно: перепечатанные вручную отзывы
устаревают и не вызывают доверия. Если нужно показывать сами отзывы в нашем
дизайне — это делается своим бэкендом (раз в сутки забирает отзывы и складывает
в JSON) или сторонним сервисом-виджетом; второй вариант вставляет чужой iframe
и будет выбиваться из оформления.

## Заставка на «Ценах»

`assets/video/intro.mp4` — ролик со старым логотипом клуба. К прайсу отношения
не имеет, стоит там как настроение: справа от заголовка «Стоимость игры».
Чёрная подложка ролика снимается через `mix-blend-mode:screen`, поэтому он
ложится прямо на звёздное небо без перекодирования файла. Разметка — константа
`PRICE_MEDIA` в `build.py`, стили — `.page-head__grid` и `.hero__frameIn--video`.

`preload="none"`: до прокрутки до прайса ролик не грузится и не тратит трафик.

## Режим работы

Клуб работает круглосуточно. Указано в надзаголовке главной, в полосе фактов,
в блоке контактов, в подвале и в микроразметке.

## Микроразметка

На каждой странице в `<head>` лежит JSON-LD `LocalBusiness`: название, телефон,
адрес, координаты, режим работы 24/7, диапазон цен, ссылки на Карты и Telegram.
Собирается в `head()` в `build.py` — правится в одном месте.

## Дизайн-решения (чтобы правки не ломали систему)

- **Цвет.** Акцент — `#F7CE43`: жёлтый из интерьера клуба (балки, рамы,
  двери). Новый логотип серебристо-синий, поэтому рядом появился второй
  голос — лёд `--ice: #59BEFF`. Он держит фон, свечение логотипа и статус
  «бронь», но кнопки, цены и цифры остаются янтарными: два равноправных
  акцента развалили бы иерархию. Фон `#0B0B0C`: тёплый чёрный, как в зале,
  а не абсолютный `#000`.
- **Фон.** Звёздное небо и северное сияние с фирменных иконок клуба.
  Один слой `.sky` на страницу, `position:fixed` — не участвует в скролле.
  Звёзды: два SVG-поля разной плотности (`stars-a.svg`, `stars-b.svg`),
  их прозрачность дышит в разном темпе — мерцание получается без JS.
  Сияние (`aurora.webp`) отрисовано заранее фильтром `feTurbulence`
  и сохранено картинкой: браузер только двигает готовый слой, а не считает
  SVG-фильтры на каждый кадр. Холст квадратный, `background-size:cover` —
  не растягивается ни на ультравайде, ни на телефоне. Лента держится
  в правой части кадра, слева остаётся чистое небо под заголовок;
  на ширине до 900px приглушается, чтобы не спорить с текстом.
  Панели полупрозрачные (`--panel`) — сквозь них читается небо. Спектральная полоска
  (подсветка клавиатур из фото зала) используется ровно дважды на странице —
  под героем и над подвалом. Больше не надо, она держится на редкости.
- **Форма.** Один срезанный угол 45° — эхо угловатого бейджа логотипа.
  Класс `.cut` / `.cut-s` / `.cut-l`. Скруглений нет нигде.
- **Шрифты.** Tektur — только короткие заголовки в верхнем регистре и номера
  мест (его кириллица хороша в крупном кегле и хуже в тексте). Manrope — весь
  текст. JetBrains Mono — подписи, данные, надзаголовки.
- **Карта зала** — главный элемент сайта. Взята из самого зала: номера машин
  нарисованы у вас на стенах, сайт повторяет эту же логику.
  Наведение на номер показывает железо этой машины, клик ведёт в бронь
  с уже выбранным местом. На тач-устройствах подсказки при наведении нет —
  там железо показывается в панели под картой после выбора места.
- Анимации уважают `prefers-reduced-motion`, фокус с клавиатуры видимый,
  контраст мелкого текста проверен (5:1 и выше).
